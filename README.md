# OZON × CDEK

Полный редизайн cdek-ozon.ru на визуальной основе OZON × DPD. Сохранены исходные условия, тарифы, все 14 FAQ, история, результаты и внешние ссылки. Никакие изменения DPD о бесплатности на CDEK не переносились.

## Запуск

Откройте `start.bat` двойным щелчком. Это единое меню вместо `install.bat`, `dev.bat`, `build.bat` и `deploy.bat`:

- **1** — запуск проекта с открытием браузера; отсутствующие зависимости устанавливаются автоматически. Для остановки сервера — Ctrl+C.
- **2** — сборка в `dist/`.
- **3** — предпросмотр сборки в браузере; если сборки ещё нет, она создаётся автоматически.
- **4** — установка или переустановка зависимостей через `npm ci`.
- **5** — сборка и полный деплой на VPS, включая сервис формы.
- **6** — отдельная сборка для GitHub Pages и публикация сайта в `gh-pages`.
- **7** — показ изменений, подтверждение, создание коммита и отправка текущей ветки исходников в GitHub. Файлы из `.gitignore` не добавляются. Для коммитов должны быть настроены `git config user.name` и `git config user.email`.
- **8** — сборка и обновление сайта на VPS без перезапуска сервиса формы.
- **0** — выход.

Нужны Node.js 22.12+ с npm; для GitHub — Git for Windows и авторизация в GitHub. Для VPS нужны локальные файлы доступа из `info/`. При ошибке последующие шаги выбранного действия не выполняются, сообщение остаётся в окне.

Кэш Vite хранится вне проекта: в `%LOCALAPPDATA%/ozon-cdek/vite/` на Windows или во временной папке системы на других ОС. Для каждой копии проекта используется отдельная подпапка. Старый кэш `node_modules/.vite` больше не используется.

После восстановления повреждённого репозитория общая база Git хранится на диске C в локальной папке `ozon-cdek/git-recovery-*/repository.git`. Точный путь указан в `.git/commondir`; эту папку нужно сохранять вместе с проектом. Обычные команды Git и пункт 7 батника используют её автоматически. Исходная повреждённая база сохранена в `.private/git-damaged-*` и в оставшейся папке `.git/objects`, которая больше не используется. Повреждённые файлы перед восстановлением скопированы в `damaged-files` рядом с новой базой Git.

Через терминал: `npm ci`, затем `npm run dev`. Сборка: `npm run build`. Предпросмотр сборки: `npm run preview`. Проверка: `npm run check`. Обработчик формы: `python server/test_leads.py`. После сборки HTML содержит всю страницу до запуска JavaScript. Для пререндеринга используется установленный Chrome; путь можно задать через `PW_EXECUTABLE_PATH`.

## Размещение

`node scripts/deploy.cjs` читает доступы из локальных `info/VPS.txt` и `info/Telegram.txt`. На VPS всё приложение расположено в `/var/www/OZON-CDEK`: `site/` — опубликованная сборка и видео; `src/`, `scripts/`, `server/`, `deploy/` — исходники и конфигурация; `data/` — SQLite заявок; `.private/` — секреты и резервная копия конфигурации. Публично доступна только `site/`. Тестовый маршрут `/OZON-CDEK/` исключён из индексации. Исходный домен и DPD сохраняются.

Форма на VPS работает через относительный `./api/leads`; Nginx направляет запрос на локальный порт 4193. Сервер проверяет источник, контакты и тариф, ограничивает запросы, сохраняет заявку в SQLite и отправляет её в Telegram. Успех возвращается после подтверждения Telegram. Повторная попытка с тем же UUID не дублирует успешно доставленную заявку. При переносе на домен следует изменить `LEADS_ORIGIN` в закрытом env, настроить TLS-виртуальный хост и убрать noindex тестового маршрута.

## GitHub Pages

Репозиторий: https://github.com/divangames/ozon-cdek. Сайт: https://divangames.github.io/ozon-cdek/. `npm run deploy:pages` собирает версию с публичным адресом обработчика VPS, выполняет пререндеринг и публикует только dist в gh-pages. Авторизация берётся из Git Credential Manager, токен не сохраняется в проект. Сборка Pages использует `VITE_LEADS_URL`; сервер допускает CORS только с адреса VPS и `https://divangames.github.io`. В открытом репозитории нет info/, приватных оригиналов и данных заявок.

Заявки с Pages помечаются в Telegram как `Источник: GitHub Pages (GitHub)` и сохраняются в базе с `source=github`. Источник определяет обработчик по разрешённому заголовку Origin; значение из формы не используется. Для остальных заявок сохраняется `source=site`. При первом запуске обновлённого обработчика существующая база получает столбец `source` без удаления заявок; экспорт CSV включает этот столбец.

## Материалы

Логотип и favicon предоставлены владельцем. Четыре снимка сделаны в действующем кабинете; ключи, реквизиты аккаунта и контакты закрыты до захвата. Видеоролики из `video/load/` оптимизированы для веб; в двух роликах убрана верхняя панель с аккаунтом. Оригиналы не изменены. Иллюстрации кейсов взяты из соответствующего блока исходного сайта. Источники указаны в `public/images/provenance.json` и `public/tutorials/provenance.json`.

Мониторинг формы: `systemctl status ozon-cdek-leads`; экспорт заявок на сервере: `sudo -u www-data env LEADS_DB=/var/www/OZON-CDEK/data/leads.sqlite3 python3 /var/www/OZON-CDEK/server/leads.py --export`. Экспорт содержит персональные контакты; хранить приватно.
